# 🐺 LocalWerewolf：局域网狼人杀自动法官

线下面杀用的自动法官。一台 Mac 运行服务器并负责语音播报，同一 WiFi 下的玩家用手机浏览器加入房间、选座、查看身份，夜间操作和白天投票也都在手机上完成。

## 快速开始

需要 Node.js 22.5 或更高版本（开发环境为 Node 26），以及 macOS（服务端语音依赖系统的 `say` 命令）。

```bash
npm install
npm run serve
```

`serve` 会先构建网页，再在 3000 端口启动服务。启动后终端会打印局域网地址，例如：

```
局域网访问：http://192.168.1.23:3000
```

- 房主在电脑上打开这个地址，注册账号，创建房间。
- 其他玩家在手机上扫描房间页的二维码（或输入地址），注册登录后选择座位。
- 房主在电脑上点「打开大屏（播报）」，把大屏页面放在桌上，所有人都能看到。
- 坐满后房主点「开始游戏」。

首次运行时如果 macOS 弹出「是否允许 node 接受传入网络连接」，请选择**允许**，否则手机无法访问。

## 管理员

首次启动时如果还没有管理员，会自动创建 `admin` 账号，随机初始密码保存在 `data/admin-password.txt`（只有当前用户可读）。登录后请在「账号设置」里修改密码，然后删除这个文件。

管理员首页会多出「管理后台」（`/admin`），可以：

- 管理用户：重置密码、设为或取消管理员、删除账号（历史对局会保留）。
- 查看所有房间：进入、打开大屏、强制关闭。
- 查看所有对局：查看复盘、删除记录。
- 在任何房间行使房主权限。

也可以在命令行管理：

```bash
npm run admin -- list             # 列出管理员
npm run admin -- create 用户名     # 新建管理员（交互输入密码）
npm run admin -- grant 用户名      # 把已有用户设为管理员
npm run admin -- revoke 用户名     # 取消管理员
npm run admin -- passwd 用户名     # 重置密码
```

## 功能

- **账号与战绩**：用户名加密码登录（bcrypt 加密），数据存在本地 SQLite（`data/werewolf.db`）。记录每局的身份、阵营、胜负和存活情况，提供战绩统计、排行榜，以及带上帝视角的历史复盘。
- **房间**：
  - 内置 10 个常见板子，也可以自定义配板（人数由配板自动计算），并保存为「我的板子」。
  - 房间号加二维码加入，选座、离座、房主踢人。
  - 「空位填充机器人」用于一个人测试。
- **自动法官**：
  - 开始后用加密随机数洗牌发身份，手机上「按住查看身份」。
  - 夜间按标准顺序逐个唤醒角色，由电脑播报「X请睁眼 / X请闭眼」，玩家在手机上操作。
  - 天亮自动结算并公布死讯。
  - 白天支持：警长竞选（上警、退水、PK、警徽移交或撕毁）、遗言、点名发言（可关闭）、放逐投票和 PK、技能发动（开枪、翻牌、自爆、决斗、白狼王带人），并自动判定胜负。
- **防泄露**：
  - 板子上的角色即使已死或不存在也照常唤醒。
  - 每个夜间步骤至少持续一个随机时长，无法从时间上判断身份。
  - 每名死者都会被询问是否发动技能，从「谁被询问」看不出猎人。
  - 服务器只把每个人有权知道的信息发给他的手机。
- **规则选项**：42 项，按常见程度分组排序，常用的默认展开，冷门的收在「高级」里。部分角色还有专属选项，例如机械狼是否必须首夜学习。
- **角色介绍**：`/roles` 页面介绍 30 个角色的技能、行动时机、新手提示、与其他角色的互动和规则变体；`/boards` 页面介绍各个内置板子。

## 发言

- 发言默认**不计时**：当前发言者在手机上点「结束发言」，房主也可以点「下一位」。
- 房主可以「跳过所有发言」，直接进入下一个环节（投票或 PK 投票）。
- 规则「发言环节」可以设为关闭，改为自由讨论，讨论结束后由房主点「开始投票」。
- 规则「发言提醒」设为大于 0 时，超时只会提醒，不会强制结束。

## 语音

语音**全部预先生成**，播报时直接播放音频文件，并且**在房主的设备上播放**：房主不需要是运行服务器的电脑。

### 在哪里播放

- 默认在房主的浏览器里播放。房主打开了「大屏」页面时由大屏播放，否则由房主当前的页面（比如手机）播放。
- 房主可以在任意设备上点「在本设备播放」，指定由这台设备负责播报。
- 浏览器要求先点一次才能出声，所以第一次需要点「开启语音」。
- 负责播放的设备会自动预加载本局常用的语音。每句播完会通知服务器，法官再进入下一步。
- 如果房主就是运行服务器的 Mac，也可以把规则「语音播放」改为「运行服务器的电脑」，由服务器用 `afplay` 直接播放。

### 预生成

```bash
npm run voice    # 首次约 15 分钟，生成后保存在 data/voice/（约 50 MB），之后启动直接复用
```

- 服务器启动时也会在后台补齐还没生成的语音。
- 模拟大量对局后自动收集所有播报模板，把座位号展开成 1～20 号的所有具体句子，一共约 2600 句，每句都**整句**用 macOS 语音合成，语调自然。
- 存储格式为 AAC（.m4a，32 kbps）。
- 只有三人及以上的名单（如「昨晚3号、5号、7号玩家死亡」）组合太多，由预先生成的片段拼接。
- 万一遇到没有缓存的句子，会当场生成并加入缓存。
- 默认使用「婷婷（Tingting）」语音，可以用环境变量 `LW_VOICE=Sandy` 等切换（中文语音列表见 `say -v '?' | grep zh_CN`）。
- 只有默认语速 190 会提前全部生成，其他语速在第一次用到时生成。
- 生成语音需要运行服务器的电脑是 macOS；播放端可以是任何带浏览器的设备。

## 开发

```bash
npm run dev        # 服务端（tsx watch，3000）+ Vite（5173，--host 允许局域网访问）
npm test           # 引擎测试：规则、角色、模糊测试、防泄露
npm run typecheck
```

项目结构：

```
packages/engine   纯函数游戏引擎（无 I/O），服务端和前端共用
  src/roles/      每个角色一个文件，在 registry.ts 中注册
  src/rules.ts    所有规则选项（按常见程度排序，第一个选项为默认值）
  src/presets.ts  内置板子
  test/           sim.ts 场景模拟器；rules/roles/fuzz 测试
packages/server   Fastify + Socket.IO + node:sqlite；房间、计时、语音、机器人、战绩
packages/client   React + Vite + Tailwind 手机优先界面
```

### 新增一个角色

1. 在 `packages/engine/src/roles/` 下新建 `xxx.ts`，导出一个 `RoleDef`，内容包括：
   - 名称、阵营、一句话介绍和 `intro`（介绍页会自动使用）
   - 夜间步骤 `night`（顺序值 `order` 决定第几个睁眼）
   - 需要时再加查验视角、死亡或放逐钩子等
2. 在 `roles/registry.ts` 的 `ROLE_LIST` 里加一行。
3. 在 `test/roles.test.ts` 中用 `Sim` 写一个场景测试。

### 环境变量

| 变量 | 默认值 | 说明 |
|---|---|---|
| `PORT` | 3000 | 服务端口 |
| `HOST` | 0.0.0.0 | 监听地址 |
| `LW_DATA_DIR` | `./data` | 数据库目录 |
| `LW_VOICE` | Tingting | macOS 语音名 |
| `LW_NO_PREGEN` | 未设置 | 设为 1 时启动不预生成语音 |
